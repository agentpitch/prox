# Управление pitchProx из CLI и агента

У приложения есть независимый от GUI интерфейс в том же исполняемом файле:

```powershell
.\pitchProx.exe ctl help
.\pitchProx.exe ctl schema
.\pitchProx.exe ctl status
```

`ctl` не запускает второй proxy, не требует UAC, не открывает браузер и не
включает WebUI. Управление работает и при выключенном/автоматически уснувшем
WebUI. Чтение конфигурации не включает сбор подробной UI-телеметрии.
Для сетевых команд должен работать экземпляр с поддержкой agent protocol v1.
У старого EXE этих команд и endpoint ещё нет. Новый CLI при обращении к старому
процессу возвращает `upgrade_required`, либо `protocol_error`, если старый
WebUI выключен и вместо agent API отвечает общим HTTP 503.

Успех возвращает JSON в stdout, ошибки — JSON в stderr и ненулевой код выхода.
`help` предназначен человеку, `schema` — агенту: команды, поля, примеры,
правила конкурентной записи и режимы применения доступны без сервера.

## Адрес и файлы

Приоритет адреса: `--url`, затем `PITCHPROX_CONTROL_URL`, затем `http.listen`
из существующего файла конфигурации установки. Путь конфигурации выбирается
из `PITCHPROX_CONFIG`, совместимого `MYPROX_CONFIG`, либо файла
`pitchProx.config.json` рядом с EXE. Если файла нет, используется
`http://127.0.0.1:18080`. Само обнаружение не создаёт и не мигрирует файлы.

```powershell
.\pitchProx.exe ctl --url http://127.0.0.1:18080 status
```

Разрешён только локальный HTTP: loopback IP или `localhost`, без proxy и
redirect. Ввод JSON ограничен 8 МиБ; неизвестные/повторные поля, несколько
JSON-документов и `null` вместо скалярных настроек отклоняются.
Поддерживаются UTF-8 с BOM и без него; неверная кодировка отклоняется.
`--file -` читает stdin.
Полный экспорт настроек содержит в том числе пароли proxy; для просмотра
только правил используйте `rules list`.

## Рекомендуемый цикл для агента

1. Прочитать `ctl schema` и `ctl status`, затем актуальные настройки/правила.
2. Подготовить правку в отдельном JSON-файле, сохранив `updated_at` из чтения.
3. Выполнить локальную валидацию и план применения.
4. Применить изменение через CLI и проверить `applied`, `plan` и новую ревизию.
5. При конфликте прочитать актуальную версию и заново совместить изменения.

Не редактируйте рабочий `pitchProx.config.json` напрямую у запущенного процесса:
он не наблюдает за файловыми правками. CLI обращается к процессу, а процесс
атомарно сохраняет и активирует конфигурацию. Нет фонового polling файла или
дополнительного постоянно работающего агента.

```powershell
# В Windows PowerShell 5.1 явно декодировать stdout EXE как UTF-8.
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)
.\pitchProx.exe ctl config get | Set-Content -Encoding UTF8 draft.json

# Изменить draft.json; updated_at оставить из оригинального экспорта.
.\pitchProx.exe ctl config validate --file draft.json
.\pitchProx.exe ctl config plan --file draft.json
.\pitchProx.exe ctl config apply --file draft.json
```

`validate` не требует сервера: проверяет настройки и синтаксис всех правил,
возвращает нормализованный документ. `plan` проверяет документ относительно
текущего процесса, но не сохраняет его, не открывает новый порт и не запускает
WinDivert. Наличие свободного порта/драйвера окончательно проверяется при apply.

`config apply` заменяет весь документ, включая массивы rules/proxies/chains.
Отсутствующая либо нулевая `updated_at` недопустима для записи. После успешного
изменения процесс выдаёт новую ревизию. Повторное применение идентичного
актуального документа возвращает `applied:false`, `mode:no_change`, не пишет
файл и не меняет ревизию. Конфигурация сохраняется и при приостановленном
runtime; новые правила будут использоваться при его возобновлении.

## Отдельные правила

```powershell
.\pitchProx.exe ctl rules list
.\pitchProx.exe ctl rules upsert --file rule.json --if-revision '<updated_at>' --before default
.\pitchProx.exe ctl rules move --id browser --before default --if-revision '<updated_at>'
.\pitchProx.exe ctl rules delete --id browser --if-revision '<updated_at>'
```

`rules list` возвращает `{updated_at,rules}`. ID — стабильный и чувствительный
к регистру. `upsert` полностью заменяет одно правило с существующим ID, сохраняя
его позицию; новое правило вставляется в указанную позицию. Без `--before` или
`--after` новое правило вставляется перед завершающим безусловным правилом
`default`, если оно есть; в пустой список добавляется первым, иначе позицию
нужно задать явно. Остальные правила,
настройки и credentials не затрагиваются. Не передавайте только изменённое
поле: вход upsert — полный объект Rule.

```json
{
  "id": "browser",
  "name": "Browser through proxy",
  "enabled": true,
  "applications": "chrome.exe; firefox.exe",
  "target_hosts": "*.example.com",
  "target_ports": "80; 443",
  "action": "proxy",
  "proxy_id": "primary",
  "notes": "Managed through ctl"
}
```

Прокси `primary` должен уже существовать и быть включён. Поддерживаются действия
`direct`, `proxy`, `chain`, `block`; `chain` использует `chain_id`.
Первое подходящее включённое правило побеждает. Язык условий описан в
[RULE_LANGUAGE.md](RULE_LANGUAGE.md). Для dry-run перестановки/удаления можно
сначала внести её в полный экспорт и вызвать `config plan`.

## Применение и непрерывность соединений

| `plan.mode` | Поведение |
|---|---|
| `no_change` | Никаких изменений и новой ревизии |
| `hot_reload` | Новые правила/proxy/settings доступны новым соединениям; установленные соединения продолжают прежний маршрут |
| `listener_rebind` | Новый HTTP-порт резервируется до сохранения; ответ уходит через старый порт, затем старый listener закрывается; PID и proxy-соединения сохраняются |
| `runtime_restart` | Меняется режим перехвата или transparent/sniff settings: routing runtime перезапускается внутри того же процесса; перехваченные соединения закрываются |

Смена HTTP-адреса и runtime могут входить в одну транзакцию: смотрите также
`http_rebind` и `runtime_restart`. `connections_preserved` описывает влияние
плана на установленные proxy-соединения, а не обещает доступность удалённой сети.
Новый адрес возвращается в `plan.listening_address` и сохранённом config.
Если задан явный `--url`/переменная окружения, обновите их для следующей команды.

Разрыв соединений по умолчанию запрещён. После просмотра плана его можно
разрешить для конкретной команды:

```powershell
.\pitchProx.exe ctl config apply --file draft.json --allow-disruptive
```

Тот же флаг есть у операций изменения правил: например, добавление первого
`proxy`/`block` правила включает перехват, удаление последнего отключает его.
Не нужен перезапуск EXE, tray или Windows Service. При ошибке bind либо
активации сохраняется/восстанавливается прежняя конфигурация; если понадобился
откат runtime, уже разорванные соединения восстановить невозможно.

## Ошибки и автоматизация

Форма ошибки: `{"error":{"code":"revision_conflict","message":"..."}}`;
ответ сервера при конфликте также может содержать `current_updated_at`.

| Exit code | Значение |
|---|---|
| 0 | Успешная операция/проверка |
| 2 | Некорректные аргументы, JSON или настройки |
| 3 | Конфликт ревизии: перечитать данные |
| 4 | Нужен явный `--allow-disruptive` |
| 5 | Приложение/операция недоступны |
| 6 | Нужна версия приложения с agent API |
| 7 | Несовместимый либо некорректный ответ протокола |
| 8 | Результат записи неизвестен после сетевой ошибки |

После таймаута записи не повторяйте её вслепую: сервер мог успеть применить
изменение. Прочитайте конфигурацию по старому/предложенному новому адресу,
сравните значения и ревизию. CLI не делает автоматических повторов мутаций.
Во время установки обновления конфигурационные изменения блокируются.

Транспорт — `/api/control/agent/*`, заголовок `X-PitchProx-Agent: 1`.
Он предназначен локальным процессам, не браузерным cross-origin запросам;
это не удалённый административный сервис и не граница прав между локальными
пользователями Windows. Детали wire protocol — [API_REFERENCE.md](API_REFERENCE.md).

Windows GUI-сборка сохраняет перенаправленные stdin/stdout/stderr, а при
отсутствующих потоках подключается к консоли родителя без открытия нового окна;
см. [AttachConsole](https://learn.microsoft.com/en-us/windows/console/attachconsole).
