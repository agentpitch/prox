# Перенос pitchProx на Rust

Rust-реализация собирается в самостоятельный `pitchProx.exe` для Windows x64. Приложение включает WinDivert и прозрачную маршрутизацию, HTTP CONNECT и SOCKS5, WebUI и API, историю, CLI, трей, интеграцию с Windows SCM и обновлятор с отдельным процессом для замены EXE. HTML, CSS, JavaScript и изображения встраиваются из того же каталога, что и в Go. Для значка EXE используется исходный ICO.

Портативная конфигурация и файлы истории сохраняют форматы Go. Rust записывает системные счётчики в диагностический JSONL. Профили Go `pprof` и счётчики сборщика мусора Go зависят от рантайма Go и в Rust отсутствуют.

## Сборка Windows

Нужны Rust и Cargo, компоновщик Windows x64 и компилятор ресурсов. Для GNU нужен `windres` в `PATH` или указанный через `WINDRES`. Для MSVC используется `rc.exe` из Windows SDK. Замеры выполнены на Rust 1.100.0 с GNU-компоновщиком.

```powershell
.\tools\build-rust.ps1 -Version dev -RequireWinDivert
.\build\rust\pitchProx.exe help
```

Скрипт проверяет SHA-256 WinDivert 2.2.2 и собирает файлы в `build\rust`. Обычный запуск использует `run`, а встроенный CLI — `ctl`. Установка Windows-службы и перехват WinDivert требуют прав администратора. Штатный `build.cmd` сохраняет сборку Go, использованную для сравнения. [Документация WinDivert](https://reqrypt.org/windivert-doc.html)

## Движок правил

Windows x64, AMD Ryzen AI 9 HX 370, Go 1.26.8, Rust 1.100.0 GNU. В обоих движках использовались одинаковые 259 правил. Показаны медианы пяти последовательных запусков каждой реализации.

| Предклассификация | Go | Rust | Во сколько раз быстрее Rust |
| --- | ---: | ---: | ---: |
| Окончательный выбор Direct по IP | 66,03 нс/операцию | 22,27 нс/операцию | 2,97 |
| Для окончательного решения нужно имя узла | 2 364 нс/операцию | 1 466,11 нс/операцию | 1,61 |

В первом сценарии выделений памяти нет. Во втором оба движка делают одно выделение на операцию. Go учитывает 24 байта выделенной памяти, Rust запрашивает у системного аллокатора 19 байт. Метрики учитывают разные стадии выделения, поэтому из них нельзя вывести разницу в памяти процессов.

```powershell
go test ./internal/rules -run '^$' -bench '^BenchmarkPreflightLargeRuleSet' -benchmem -count 5 -cpu 1
cargo bench --locked --bench rules
cargo bench --locked --bench rules --features bench-allocations
```

## Измерение процессов Windows

Эталон собран штатным `build.ps1` на Go 1.26.8. Для каждого запуска используются отдельный временный порт, одинаковые правила Direct и чистая история. Обе версии запускаются в режиме `run` с включённым треем. Каждый из двух сценариев длится 15 секунд. В активном сценарии клиент запрашивает `/api/snapshot?include_logs=0` два раза в секунду. Снимать показатели нужно при закрытых браузерных сессиях и отдельно от сборки.

Медианы трёх запусков на каждую сборку. Между повторами порядок Go и Rust менялся.

| Показатель | Go | Rust | Разница Rust к Go |
| --- | ---: | ---: | ---: |
| Private bytes, простой | 15,89 МиБ | 1,78 МиБ | −88,8% |
| Working set, простой | 16,84 МиБ | 11,98 МиБ | −28,9% |
| Private bytes, мониторинг | 22,36 МиБ | 2,79 МиБ | −87,5% |
| Working set, мониторинг | 22,20 МиБ | 12,97 МиБ | −41,6% |
| Время CPU, мониторинг | 109,38 мс | 171,88 мс | +57,1% |
| Доля одного ядра, мониторинг | 0,73% | 1,15% | +0,42 п.п. |
| Задержка ответа мониторинга | 6,18 мс | 7,58 мс | +22,6% |
| Размер EXE | 5,81 МиБ | 2,80 МиБ | −51,8% |

В простое время CPU обеих версий было ниже разрешения счётчика. При мониторинге доля одного ядра менялась от 0,42% до 1,04% у Go и от 1,04% до 1,66% у Rust. В этой конфигурации Rust расходует меньше памяти, а обработка мониторинга стоит больше процессорного времени. Сценарий с правилами Direct не активирует драйвер, поэтому эти цифры не характеризуют расход ресурсов при ретрансляции трафика. Исходные замеры находятся в `build/rust-comparison/desktop-go-vs-rust.json`.

```powershell
.\build.ps1 -Version dev -OutputDirectory build/rust-comparison/go -OutputName pitchprox-go.exe
.\tools\build-rust.ps1 -Version dev -RequireWinDivert
.\tools\compare-runtime.ps1 -GoExecutable .\build\rust-comparison\go\pitchprox-go.exe `
    -RustExecutable .\build\rust\pitchProx.exe -Seconds 15 -Repeats 3 -UseTray
```

## Проверки

```powershell
cargo fmt --all --check
cargo clippy --locked --all-targets --all-features -- -D warnings
cargo test --locked --release
go test ./internal/... ./cmd/...
node --test internal/webui/lifecycle_test.js internal/webui/rules_ui_test.js
node tools/verify-rust-parity.mjs build/rust-comparison/go/pitchprox-go.exe build/rust/pitchProx.exe
```

В сравнительном тесте запускаются два EXE с одинаковыми данными. Он проверяет ресурсы, ошибки API, состояние WebUI, чтение истории Go, API и CLI, смену ревизии конфигурации и HTTP-порта и согласование HTTP CONNECT с локальным сервером. Отдельный Rust-тест проверяет наблюдение, получение и передачу блокировки helper, замену и подтверждение состояния после повторного запуска временной копии EXE.

Снимки Playwright страницы правил и редактора правила при одинаковом размере окна 1280 × 900 совпали побайтно. Снимки сохранены в `output/playwright/rust-parity`.

Сквозная проверка WinDivert и команд Windows SCM требует повышенных прав. Тестовый Windows Sandbox не вернул результат, поэтому фактический перехват драйвером и запуск через SCM на этом хосте не подтверждены. Сценарий для изолированной Windows находится в `tools/verify-windows-sandbox.ps1`. Тест обновлятора использует локально подготовленный EXE, поэтому дополнительно остаётся проверка скачивания и установки опубликованного релиза.
